# 公众号平台约束

写公众号和写博客不一样的地方，几乎全在这儿。内容写得再好，撞上平台规则一样白干。

这份文档只写**平台层面的硬约束和结构性坑**，不谈文笔。具体数值不写在正文里，统一放在
[`platform-limits.json`](platform-limits.json)，由 [`../scripts/check_mp.py`](../scripts/check_mp.py) 读取。
微信的限制会变，把数字散在文档里迟早变成过期的假权威。

> 下面标了「会变」的项目，用之前请按 `platform-limits.json` 里的 `verifyAgainst` 核对官方文档。

## 一、链接：这是最常见的翻车点

**公众号正文里的外部链接不可点击。** 读者看到的是一串纯文本 URL，只能手动抄到浏览器。这条几乎劝退了所有从博客直接搬运的稿子。

能放链接的位置只有几个：

| 位置 | 说明 |
| --- | --- |
| 阅读原文 | 每篇文章一个，放最重要的那个链接 |
| 公众号名片 | 链接到自己或他人的公众号 |
| 已认证服务号的部分场景 | 规则和账号类型强相关，会变 |

所以写作时的正确做法是：**正文里不要出现第二个链接**。需要引流就用「阅读原文」、二维码图片，或者引导文字（"公众号后台回复 xxx"）。

`check_mp.py` 的 `link` 检查就是卡这一条。它统计正文里所有 http(s) 链接，多于零就报错——不是因为一个都不能有，而是提醒你把它挪到「阅读原文」。

## 二、标题

- 标题在后台**单独填写**，正文里不要再写一遍，更不要用 H1。正文小标题从 `##` 起。
- 超长会在列表页和分享卡片被截断，上限见配置文件（会变）。
- 真正的约束不是字数上限，是**手机列表页的一行能显示多少**。20 字以内比较稳，再长就折行，折行后的观感差别很大。
- 标题是列表页里唯一的点击理由。摘要在很多入口根本不显示。

## 三、摘要

留空的话微信会自动截取正文开头填充，通常从第一句话硬切，很难看。手动写。

上限见配置文件（会变）。写的时候当成"第二个标题"，不要复述正文第一段。

## 四、封面图

| 位置 | 比例 |
| --- | --- |
| 头条 | 2.35:1 |
| 次条 | 1:1 |

关键在于：**同一张图会被按不同比例裁剪**，主体放中间，重要文字不要贴边。分享到朋友圈、聊天窗口时又是另一套裁剪逻辑，多留白是唯一稳妥的做法。

## 五、代码块

正文宽度是固定的，代码块超宽只能横向滚动，手机上基本没法读。

- 控制每行宽度，上限见配置文件（这是经验值，不是平台规定）
- 长命令用 `\` 断行
- 实在放不下的，用截图代替，配深色主题

## 六、排版

Markdown 不能直接粘进公众号编辑器，需要先转成带内联样式的富文本。可以用
[mdlook](https://github.com/mxx1111/mdlook)（Markdown 排版 + 公众号复制，Mac 本地工具）。

排版环节常见的坑：

- 段落之间要有间距，公众号默认行距偏紧
- 引用块、列表的样式在不同编辑器里差别很大，转换后要肉眼过一遍
- 表格在手机上会压缩，超过三列就该考虑改成列表
- Emoji 在部分安卓机上显示为方块

## 七、发布节奏

- 订阅号和服务号的群发次数不同，且和认证状态相关（会变）
- 群发后**不能修改**，只能删除重发，重发会丢掉已有的阅读量和在看
- 定时发送可以撤销，已群发的不行

所以体检要在发布**之前**做。`check_mp.py` 的意义就在这儿——发出去才发现代码块横向滚动，就只能重发。

## 八、原创声明与留言

这两项的规则历史上调整过多次，且和账号注册时间、认证状态强相关。**不要凭记忆操作**，以后台当前显示为准。

能确定的只有一条：原创声明一旦提交**不可撤销**，转载授权设置也会跟着生效，发之前想清楚。

## 九、发布前检查清单

```bash
python3 scripts/check_mp.py article.md --title "标题" --digest "摘要"
```

机器能查的它都查了。剩下这些得人看：

- [ ] 封面图在头条比例和次条比例下裁剪都正常
- [ ] 「阅读原文」链接指向正确
- [ ] 引用的数据有出处，且出处可核
- [ ] 涉及具体人和机构的表述已核实
- [ ] 排版后在手机上完整读一遍

最后一条最容易省略，也最容易出事。
